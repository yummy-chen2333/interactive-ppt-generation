# 交互式 PPT Generation Skill 需求与工作流规范

**文档状态**：Draft v0.3  
**当前范围**：固定产品目标、用户交互、内容所有权、逐页制作规划、后端复用边界及不可覆盖的 PPTX 版本发布。

## 1. 产品目标

构建一个可被 Coding Agent 调用的交互式 PPT Generation Skill。系统通过多轮交互确认演讲需求，完成内容与页面规划，并在用户确认后准备素材、生成逐页 SVG，最终转换为原生可编辑 PPTX。

**核心交付**：

- 一份内容与页面逻辑经用户确认的 PPTX。
- 一份有事实依据、按页组织并能驱动素材搜索的完整演讲讲稿。
- 每页文字、图片、排版和来源都有对应的中间记录。
- 用户可按页提出修改，系统修改对应规划和 SVG 后重新导出。

逐页讲稿保存在 `narrative/speaker-notes.md`。后续可增加独立 Word 导出器；v0.3 只保证讲稿源文件完整，不把 Word 文件列为已实现交付物。

---

## 2. 运行边界

| 层级 | 职责 |
|---|---|
| Coding Agent 聊天界面 | 需求询问、方案展示、用户确认、修改反馈 |
| 本地 Skill 工作区 | 内容规划、模板分析、素材管理、SVG 生成、质量检查和版本记录 |
| PPT Master 转换后端 | 仅检查本项目已完成的规范 SVG，并转换为 DrawingML/PPTX |
| PowerPoint | 查看、演示和进一步人工编辑最终 PPTX |

**范围约束**：第一版不开发独立网页、实时可视化编辑器或多人协作系统。

**后端边界**：PPT Master 的转换代码及必要依赖复制到本 Skill `scripts/` 内作为本地转换库，不要求使用者另行下载 PPT Master，也不作为第二套 Skill 或第二套工作流运行。禁止再次进入其需求确认、内容规划、模板选择、确认网页和 SVG 编辑网页。

---

## 3. 总体流程

```text
用户请求
→ 第一轮：确认是否有模板
→ 第二轮：确认主题、受众、页数和演讲文本
→ 模型规划 PPT 类型、大板块和逐页内容
→ 第三轮：确认文字版 PPT 方案
→ 第四轮：整体或局部内容修改并最终确认
→ 第五轮：逐页收集用户自有图片
→ 模板或自由设计分析
→ 检索事实资料并编写逐页完整讲稿
→ 从讲稿提取视觉目标并搜索图片
→ 生成结构化上屏文字、图片与排版方案
→ 生成符合 PPT Master 规范的逐页 SVG
→ SVG 质量检查、文字溢出与图文碰撞预览
→ SVG 转 DrawingML 并导出 PPTX
→ 发布为唯一版本文件并记录 SHA-256
→ 用户按页反馈
→ 更新对应页面规划与 SVG
→ 重新检查并导出新版本
```

**Hard rule**：第四轮的内容定稿确认完成前，不搜索图片、不生成图片、不进行页面视觉制作。

### 3.1 项目内容分层

每次 PPT 使用独立项目工作区：

| 层级 | 所有内容 |
|---|---|
| `inputs/`、`research/` | 用户原始材料、外部事实、图片搜索过程、数据、人物故事和来源 |
| `narrative/` | PPT 类型、板块、逐页目的、核心观点、完整讲稿和衔接 |
| `ppt-content/` | 最终上屏文字、图片、原创 SVG、背景和页面结构 |
| `production/` | 每页如何引用并组合已经锁定的 PPT 内容 |
| `spec_lock.md` | 从已定稿设计投影出的后端技术参数 |
| `svg_output/` | 按逐页施工图生成的完整 SVG 页面 |

`narrative/` 不保存上屏排版，`ppt-content/` 不保存长篇讲述逻辑，`production/` 不创造新内容。

---

## 4. 第一轮：模板路由确认

### 4.1 用户问题

```text
是否有希望参考或复用的 PPT 模板/历史优秀 PPT？
```

### 4.2 路由行为

| 用户回答 | 路由 |
|---|---|
| 有模板 | 记录模板文件，后续进入模板学习路线 |
| 无模板 | 后续进入自由设计路线 |

两条路线在本轮后均进入第二轮。

模板问题在全流程只询问一次。用户上传模板后，该文件直接成为第 10 节的学习对象；后续不得再次要求选择 PPT Master 模板、设计风格或生成路线。

---

## 5. 第二轮：PPT 基本需求确认

| 字段 | 必需 | 行为 |
|---|---|---|
| PPT 主题 | 是 | 记录演讲核心议题 |
| 目标受众 | 是 | 记录受众身份与专业背景 |
| 页数要求 | 否 | 有要求时约束规划；无要求时由模型建议 |
| 演讲稿或文字材料 | 否 | 用户可粘贴文本或提供文件 |

系统展示完整摘要并等待用户确认。

---

## 6. 内容规划

用户确认基本需求后，模型按以下顺序进行文字规划：

1. 根据主题与受众判断 PPT 类型。
2. 根据 PPT 类型确定整体表达逻辑。
3. 将演讲拆分为若干大板块。
4. 确定每个板块必须说明的内容。
5. 将各板块内容拆分为若干页 PPT。
6. 为每页编写页面标题、页面目的、核心观点和必须讲述的具体内容。

**本阶段边界**：只规划演讲与页面内容，不决定图片、素材或视觉排版。

---

## 7. 第三轮：文字版 PPT 方案确认

系统按以下三层结构展示方案：

### 7.1 PPT 类型

说明判断的 PPT 类型及判断依据。

### 7.2 大板块设计

展示板块名称、板块目的、板块顺序和板块之间的逻辑。

### 7.3 逐页文字方案

每页至少包含：

| 字段 | 含义 |
|---|---|
| 页码 | 页面唯一编号 |
| 页面标题 | 本页的主题 |
| 页面目的 | 本页对整体演讲起到的作用 |
| 具体内容 | 本页必须向受众展示的信息 |

系统展示完整方案后等待用户确认或提出修改。

---

## 8. 第四轮：内容修改与定稿

| 修改类型 | 行为 |
|---|---|
| 局部修改 | 修改指定页的标题、目的或具体内容 |
| 整体修改 | 重新调整 PPT 类型、板块结构、页数、顺序或逐页内容 |

修改后重新展示完整文字方案。用户明确确认后，内容规划进入锁定状态。

---

## 9. 第五轮：用户图片收集

内容定稿后，系统询问用户每一页是否有指定图片、Logo、截图或照片。

| 状态 | 行为 |
|---|---|
| 用户有图片 | 将图片保存到对应页面的用户素材目录 |
| 用户无图片 | 保留对应页面的空目录 |

用户提供的图片在后续素材选择中具有最高优先级。

---

## 10. 模板与自由设计

### 10.1 模板学习路线

分析用户模板的：

- 页面背景与配色。
- 标题、正文的字体与字号层级。
- 常见图文排版。
- 文本框与图片框的位置、大小和比例。
- 不同页面类型的组织方式。

该分析由本项目完成，不把参考 PPT 转入 PPT Master 的 Create Template、Fill Template 或 Generate 路线。

### 10.2 自由设计路线

根据 PPT 类型与受众建立统一设计系统。可检索同类型优秀 PPT 的设计资料，但不直接复制具体页面。

输出应包含：

- 整体背景与配色。
- 字体与字号层级。
- 通用留白和对齐规则。
- 各页的文字与图片区域。

---

## 11. 资料与图片获取

这里的“图片”按视觉素材理解，同时包含项目自制的可编辑 SVG 示意图。用户图片、网络图片与 AI 图片主要承担真实场景、人物和产品展示；原创 SVG 主要承担流程、结构、时间线、对比和抽象概念说明，并在素材准备阶段保存到对应页面目录。

原创 SVG 的信息依据必须可追溯，文件来源标记为“项目自制”。它在逐页制作方案确定后进入页面 SVG，转换后应尽量保留为可编辑的 DrawingML 文字、形状和路径。

### 11.1 事实资料

当用户材料不足以支持已确认的页面内容时，检索必要的外部资料。外部事实、数据和引用必须记录来源。

根据页面意图和已核实资料，为每页编写 `narrative/speaker-notes.md`。每页讲稿包含开场句、完整口语讲述、证据编号、与画面的对应关系和页面衔接。讲稿默认不必完整展示给用户，但必须保存，并作为未来 Word 汇报稿的来源。

### 11.2 讲稿驱动的图片搜索

从讲稿提取具体人物、设备、事件、年份、机构、地点、场景和关系结构。将讲稿依据、视觉目标、搜索词、候选 URL、判断和最终选择写入 `research/image-search-log.md`。

不得只使用页面标题或空泛的页面目的搜索图片，也不得为整套 PPT 统一选择“全原创 SVG”。逐视觉目标分类：具体人物、设备和事件使用真实证据路线；可拍摄的课堂、科研、协作和校园活动使用现实场景路线；流程、机制和结构关系使用原创 SVG；同页兼有两类内容时分别准备并组合。

适合真实照片的目标必须记录实际搜索词与候选 URL，或记录多个查询均失败的明确说明。缺少搜索证据、用原创 SVG 绕过真实照片目标，或混合页面只准备原创 SVG 时，素材阶段不得通过。

### 11.3 图片优先级

```text
用户提供的图片
→ 网络搜索到的可用图片
→ AI 生成图片
→ 缺失标记或占位符
```

**Hard rule**：不得伪造图片、数据、实验结果或引用来源。

## 12. 逐页制作方案

从逐页讲稿提炼最终上屏文字并写入 `ppt-content/text/slide-copy.md`，不要把完整讲稿复制到页面。把图片和原创 SVG 保存到 `ppt-content/visuals/`，把最终设计写入 `ppt-content/design/`。随后在 `production/slide-production-plan.md` 中形成完整制作方案。

| 类别 | 必需信息 |
|---|---|
| 文字 | 独立内容键、标题、段落、要点、图注、位置、安全区、字体、字号、行距和最大行数 |
| 图片 | 路径、来源、用途、位置、大小和裁剪方式 |
| 背景 | 颜色、图形、图片或模板来源 |
| 排版 | 页面结构、对齐、间距、图文比例 |
| 视频占位 | 是否使用、预留位置和尺寸 |

每页文字按标题、段落、要点、图注和来源拆为独立对象，不得把整页文字写成一个对象。文字框与图片框不得非预期相交；施工图、SVG 预览和最终 PPTX 的检查结果写入 `production/layout-review.md`。

文字无法容纳时依次精简上屏文字、重新分段、扩大文字区域、调整布局，最后才小幅调整字号；不得通过极小字号、负行距、裁切或压入图片区域强行容纳。

本阶段结束时，每页的文字、图片和排版必须已经确定，不得在 SVG 生成阶段重新选择素材或更改页面主旨。

设计定稿后生成项目根目录的 `spec_lock.md`。它只服务质量检查器与转换器，不替代 `ppt-content/design/` 中的完整设计记录。

## 13. SVG 与 PPTX 生成

### 13.1 SVG 生成

- 每页 PPT 对应一个 SVG 文件。
- SVG 实现已确认的逐页制作方案。
- SVG 必须符合 PPT Master 的项目规范和转换器支持边界。
- 不得将任意浏览器 SVG 直接交给转换后端。

### 13.2 质量检查与导出

```text
svg_output/*.svg
├─→ svg_quality_checker.py → 质量报告
├─→ finalize_svg.py → svg_final/*.svg
└─→ svg_to_pptx.py → 临时 PPTX
                         └─→ publish_version.py → exports/V<NNN>_<title>_<timestamp>.pptx
```

**编辑性边界**：受支持的 SVG 文字、形状和路径转换为 DrawingML 对象；照片和 AI 生成图片作为独立图片对象插入。

**调用边界**：只复用上述三个 PPT Master 转换脚本及其必要依赖。不得调用 PPT Master Skill、路由、完整 Generate 工作流、确认网页或浏览器编辑器。

**发布边界**：转换器输出是临时文件，不能直接作为长期交付文件。每次使用本项目的 `publish_version.py` 生成不可覆盖的新版本，并更新 `exports/latest.json`、追加 `exports/publish_history.jsonl`。

**可移植运行入口**：GitHub 使用者在 Skill 根目录执行 `python -m pip install -r requirements.txt`，随后通过 `python scripts/run_backend.py <project_path>` 完成检查、预览、DrawingML/PPTX 转换与版本发布，不解析外部 PPT Master 路径。

---

## 14. 用户按页修改

用户以页码指定需要修改的页面，并说明问题和期望结果。

| 反馈类型 | 处理 |
|---|---|
| 文字修改 | 更新该页文字方案并重新生成 SVG |
| 图片替换 | 更新该页素材与来源记录并重新生成 SVG |
| 排版修改 | 更新该页排版方案并重新生成 SVG |
| 整体结构修改 | 返回内容规划阶段，重新确认页数、顺序和逐页内容 |

修改后重新运行 SVG 质量检查与 PPTX 导出，并发布为新的唯一版本号。发布后必须按 `latest.json` 的绝对路径重新读取或渲染该文件，检查修改页确已变化，再向用户交付。不得覆盖同名文件或打开 PowerPoint“最近使用”项来验证。

---

## 15. 来源与第三方复用

### 15.1 素材来源

对每个外部素材记录：

- 使用页码。
- 本地文件路径。
- 来源类型。
- 来源网站或 URL。
- 获取时间。
- 生成方式（如适用）。

### 15.2 PPT Master 复用边界

| 部分 | 所有权说明 |
|---|---|
| 交互、内容规划、模板分析、素材管理、版本修改 | 本项目设计与实现 |
| SVG 质量检查、预处理、SVG 到 DrawingML/PPTX 转换 | 复用 PPT Master |

提交物必须保留 PPT Master 的项目来源、使用版本或 commit、MIT 许可证及必要的版权说明。

---

## 16. 第一版不支持范围

- 独立网页编辑器。
- 自动启动 PPT Master 的确认网页或 SVG 编辑网页；仅当用户明确要求浏览器预览时，可临时提供本项目的只读预览。
- 多人实时协作。
- 音频旁白和动画定制。
- 视频内容处理；只允许预留视频位置。
- 同时输出 HTML Presentation。
- 运行时多 Skill 协同；所需能力作为本项目内部工具集成。

---

## 17. 阶段验收标准

| 阶段 | 完成条件 |
|---|---|
| 需求确认 | 模板路由、主题、受众、页数和演讲文本状态已确认 |
| 内容定稿 | PPT 类型、大板块、页数和逐页文字方案已确认 |
| 讲稿完成 | 每页完整讲稿存在，事实可追溯，并标明与画面的关系 |
| 素材就绪 | 用户素材已收集；逐目标类型明确；真实照片目标具有搜索证据或明确失败记录；混合页面两条路线都已完成 |
| 逐页方案完成 | 每页结构化文字、图片、背景、排版、容量和来源记录完整，施工图碰撞检查通过 |
| SVG 就绪 | 每页 SVG 存在并通过质量检查及视觉布局验收 |
| PPTX 就绪 | PPTX 可打开，页数正确，关键文字和形状可编辑，最终换行和图文位置复查通过 |
| 版本修改完成 | 用户指定页已更新；新版 PPTX 使用唯一文件名发布；`latest.json` 路径、SHA-256 和修改页核验一致 |
